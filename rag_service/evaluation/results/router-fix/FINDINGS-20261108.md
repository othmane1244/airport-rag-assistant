# Router fix — findings (2026-11-08, branch fix/router)

Raw results: `router-fix-aga-rag-v2-150-20261108T152055Z.json` (tuning set) and
`router-fix-aga-router-holdout-v1-20261108T152148Z.json` (held-out set, run once, committed
unmodified). Script: `backend/api_service/scripts/evaluate_router_fix.py`. "Before" = the router on
`main`, "after" = this branch, in the same run.

## Benchmark v2 (150 questions) — used to design the rules and set the threshold

| | Before | After | McNemar (exact) |
|---|---|---|---|
| Router accuracy | 86.7 % [80.3 ; 91.2] | 100 % [97.5 ; 100] | 0 vs 20, p < 0.001 |
| A + router, Hit@3 (120 answerable) | 85.8 % [78.5 ; 91.0] | 93.3 % [87.4 ; 96.6] | 0 vs 9, p = 0.0039 |
| A + router, Arabic | 72.5 % | 87.5 % | |

Distance gate: threshold 1.18 = smallest 0.01 value that blocks no answerable question. It blocks
**none** of the 150 benchmark questions: the 30 in-scope unanswerable questions are as close to the 73
`voyageur` passages (best distances 0.674–1.117) as answerable ones (up to 1.179).

These numbers are **optimistic by construction**: the rules were written from this benchmark's 20
errors, and the benchmark has no off-topic question.

## Held-out set (60 questions, never used for tuning, run once)

| | Before | After | McNemar (exact) |
|---|---|---|---|
| Router alone | 56.7 % [44.1 ; 68.4] | 60.0 % [47.4 ; 71.4] | 11 vs 13, p = 0.84 |
| Router + distance gate | 56.7 % | 65.0 % [52.4 ; 75.8] | 9 vs 14, p = 0.40 |

By group (correct decisions, before → after with gate):

| Group | n | Before | After |
|---|---|---|---|
| In scope, documentary | 24 | 16 | 21 |
| In scope, live flight without number | 6 | 0 | 4 |
| Off topic, plain | 16 | 14 | 14 |
| Off topic, confusable (airport-like words) | 14 | 4 | **0** |

**Reading:** no significant change overall. The fix trades off-topic rejection for in-scope recall:
in-scope questions are much better handled (16/30 → 25/30), but confusable off-topic questions
("the bus in my neighbourhood", "reset my Wi-Fi router", "hotel near Agadir") now all reach the RAG
and the LLM. The distance gate stops only 5 of the 30 off-topic questions: off-topic best distances
range from 0.86 to 1.39, and the 16 that pass (0.86–1.16) overlap the in-scope range, because the passenger search space is only 73 passages.
`ho_fr_in_03` ("film plastique" for luggage wrapping) is wrongly refused because of the off-topic
term "film".

Consequences: with this fix, off-topic messages rely on the LLM system prompt to refuse, and they
consume LLM quota. A distance threshold is not a reliable off-topic detector on this corpus.

Note: the author of the fix also wrote the held-out set (before the fix), so this measurement is not
fully blind.

## Confusable off-topic questions sent to /chat (decisive test before merging)

`confusable-chat-20261108T172832Z.json` (14 replies) and
`confusable-classification-20261108T172832Z.json` (manual reading by the coding assistant).
Stack: fix/router at commit `a359032`, AUTH_DISABLED local override, no rule changed before the run.

| Outcome | Count |
|---|---|
| Correct abstention (declines or "no information", no fact given) | **14** |
| Off-role answer with unrelated airport information | 0 |
| Invented answer | 0 |

- Engines: 12 LLM refusals (Gemini 2, Groq 10, Gemini free-tier quota exhausted) and 2 fixed
  `no_result` messages ("I don't have that information... contact the airport", safe but oddly worded
  for a home router or a neighbourhood bus).
- Cost: 12 of 14 off-topic questions consumed an LLM call.
- Side issue: the 12 refusals still display **unrelated sources** (e.g. "Taxi & Bus.pdf" next to the
  refusal about a neighbourhood bus). The UI therefore shows citations that justify nothing.
- One refusal (`ho_fr_off_10`) adds a suggestion to ask about the airport's phone services; no fact
  is given.

So, on these 14 questions, the cost of "documentary by default" is LLM quota and misleading source
labels, not wrong answers. This relies on the LLM system prompt; 14 questions do not prove it holds in
general.

## Change made after the held-out measurement

- `"film"` / `"movie"` were removed from the off-topic list and replaced by entertainment phrasings
  ("regarder un film", "un bon film", "watch a movie", "good movie", "مشاهدة فيلم"), because
  `ho_fr_in_03` ("film plastique") was wrongly refused. **This change was made after the held-out
  set had been measured. The held-out set was NOT re-run**, so its figures above describe the router
  before this change. Benchmark v2 router accuracy is unchanged (150/150). Unit tests added.

## Limites de la mesure (measurement limits)

- **Small held-out set:** 60 questions (30 in scope, 30 off topic, 14 confusable). 95 % Wilson
  intervals are about ±12 points overall and much wider per group; McNemar tests on 60 paired
  questions have little power. Differences of a few questions are not interpretable.
- **Not independent:** the held-out set was written by the coding assistant that also designed the
  fix, not by an independent human. It was written and frozen (SHA-256) before the fix, but the same
  author's phrasing habits may favour the rules. An independent set written by someone else is needed.
- **100 % on the benchmark is not a result:** the router rules and the distance threshold were set on
  this same 150-question benchmark (from its 20 errors), and the benchmark contains no off-topic
  question. The benchmark figures show the fix covers the cases it was built for, nothing more.
- The /chat classification of the 14 confusable replies was also done by the coding assistant.
- **Known limit, not fixed:** when the LLM declines an off-topic question, `/chat` still returns the
  retrieved sources and the UI displays them next to the refusal (12 of the 14 confusable replies).
  These citations justify nothing. Decided not to fix before the defence; also listed in the README.
- After this measurement, the fixed `no_result` text was made neutral in the three languages ("I could
  not find this information in the airport's documents." instead of "...please contact the airport
  directly"). Rules and threshold unchanged.
