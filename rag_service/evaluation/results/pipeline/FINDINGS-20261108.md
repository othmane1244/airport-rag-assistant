Table: `summary-20261108T133711Z.md`. Raw results: `pipeline-{A,B,D}-*.json`, `router-*.json`,
`chunking-*.json`. Scripts: `backend/api_service/scripts/evaluate_pipeline.py`,

## Read this first

- **The topic rules and the query expansion were tuned while looking at this same benchmark.** Config
  A's scores are therefore probably optimistic compared with B, C and D. A clean comparison needs
  a held-out question set written after the rules were frozen.
- 120 answerable questions: one question = 0.83 points of Hit@3. One run per configuration.
- **None of the Hit@3 differences between A, B and D is statistically significant** (exact McNemar:
  A vs B p = 0.25, B vs D p = 1.00). The 95 % Wilson intervals overlap widely (A [87.4 ; 96.6],
  B [84.3 ; 94.8], D [83.3 ; 94.2]). The differences below are **trends**, not demonstrated effects.
- All configurations ran on the same index on the same day. The index changed after the
  2026-10-10 archive: the "Car rent" PDF (and two "Boutiques" PDFs) were re-ingested on 2026-10-11
  16:46 UTC (Chroma operation log: delete then upsert of the same ids, text re-extracted), which moves
  2 questions; B (90.8 %) is therefore not directly comparable with the archived 92.5 %.
- The passenger search filters on audience `voyageur`, which covers **73 of the 15,346 passages**
  (50 PDFs). The other 15,273 passages are never searched by `/chat`.

## Results

| | Hit@3 | 95 % CI | MRR@5 | Recall@5 | 0 passage (answerable) |
|---|---|---|---|---|---|
| A — expansion + topic filter (current) | 93.3 % | [87.4 ; 96.6] | 0.872 | 91.7 % | 5 |
| B — expansion only | 90.8 % | [84.3 ; 94.8] | 0.796 | 89.4 % | 0 |
| C — expansion + reranker | **not run** (perspective) | | | | |
| D — raw dense retrieval | 90.0 % | [83.3 ; 94.2] | 0.794 | 89.4 % | 0 |
| A + keyword router (what /chat really does) | 85.8 % | [78.5 ; 91.0] | 0.807 | 84.8 % | 15 |

- **Expansion (B vs D):** +1 question (`ar_iata`), no question lost. Trend only (p = 1.00).
- **Topic filter (A vs B):** +3 questions (`en_bus_stops`, `ar_rental`, `fr_bus_route`), no hit lost,
  MRR +0.076. Trend only (p = 0.25). Cost: 5 answerable questions end with 0 passages (`ar_checkin`, `ar_departure`,
  `ar_currency_post`, `en_bus_route`, `ar_bus_route`); all 5 were already misses in B. In /chat the
  user then gets the fixed "no document found" message instead of an answer from wrong passages.
  The filter never emptied an unanswerable question.
- **Keyword router:** 86.7 % accuracy (Arabic 76 %). 14 in-scope questions are sent to
  `out_of_scope`, 10 of them answerable, so they never reach retrieval: A's 93.3 % drops to 85.8 % once
  the router is included (Arabic 72.5 %). 6 of the 9 live-flight questions are not recognised as
  flight questions (only those with a flight number are). The benchmark has no truly off-topic
  question, so the router's rejection ability is not measured.
- **Reranker (C):** left as a perspective. Code implemented and unit-checked (ordering, filter interaction), not measured.
  `BAAI/bge-reranker-v2-m3` weights (2.27 GB) could not be downloaded: HuggingFace and a public mirror
  both served about 6–8 kB/s on 2026-11-08.
- **Chunk size:** 800/150 vs 1200/150, both rebuilt from the 50 voyageur PDFs in separate collections
  (Mistral OCR off). 1200: 60 passages, Hit@3 90.8 %; 800: 81 passages, Hit@3 89.2 % (−2 questions,
  both French), recall@5 +0.8 point. No meaningful difference on this set. The 1200 rebuild
  produced 60 passages, not the 73 of the main index, so it is not an exact copy of it.
- Latency (retrieval chain, client side, median): 183–191 ms for A, B, D.
